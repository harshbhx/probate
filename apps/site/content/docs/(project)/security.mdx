## What's protected

| Asset | Why it matters |
| --- | --- |
| The owner's rules, contacts and preferences | A poisoned rule changes how every future generation behaves |
| Payment and identity decisions | The most valuable target for a scammer |
| The genome | If weakened, every generation loses its resistance |
| Connector credentials | They unlock mail, the archive and the models |

## Defences, stage by stage

| Stage | Defence | Stops |
| --- | --- | --- |
| Arrival | Inherited instincts, asked through Jev before the brain reads anything | Tricks the family has met before, in any language |
| Life | Every memory tagged with its source; replies drafted only to the owner | Silent spread; a fooled agent acting outside |
| Death | The Sprite is deleted after the disk is compared with its birth | Cron jobs, shell hooks, planted programs |
| Trial | Code checks, then Jev with per-answer confidence; items wrapped as data | Payment redirects, fake trust, removed checks, hidden text, fake authority, court injection |
| Doubt | Anything unclear is held for the owner; unanswered means not inherited | Outages and edge cases |
| Learning | An instinct must stay silent on every harmless twin | Instincts that would block normal mail |
| Keys | Connectors keep every vendor key off every Sprite | Credential theft from a fooled generation |
| Public site | Answers come only from records, refuse instructions, hide addresses, are rate-limited | Injection and leaks through "Ask an ancestor" |

## What the court can miss

<Callout type="warn" title="Published on purpose">
  These limits are also on the live site's evidence page.
</Callout>

1. **Harmless-looking poison.** An item can look innocent alone ("Rishi prefers payment links over invoices") and still help a later trick. Provenance helps and doubt goes to the owner, but some will pass.
2. **Steering the judge.** Injected text can still shift a model's scores even when answers are typed. The code checks can't be talked to, but a careful attacker might move Jev.
3. **Overfitted instincts.** An instinct from one example may miss a very different version of the trick, or block a rare legitimate email.
4. **Owner impersonation.** Mail from an address on the owner's list is treated as the owner, including decisions on held items. AgentMail leaves out unauthenticated mail by default, which stops a plain forged sender, but Probate relies on that rather than checking DKIM and SPF itself.
5. **Our numbers come from our own suite.** Sixteen tricks in four languages is a start, not a benchmark.

## Safety of the project itself

- Test emails use `.example` addresses and go only to our own inboxes.
- Disk attacks are harmless canaries that never leave the generation's Sprite.
- A fooled generation can only draft replies to the owner, so it can't send money or data anywhere.
- No real payment details, credentials or third-party personal data are used.

The full threat model with every known limitation and the hardening still to do is in [docs/SECURITY.md](https://github.com/harshbhx/probate/blob/main/docs/SECURITY.md).
