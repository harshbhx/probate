## What goes where

| Part | Hosted on | Deployed by |
| --- | --- | --- |
| The Courthouse and the live-family site | Fly.io Sprites (`probate-courthouse`) | `scripts/deploy.py` |
| Generations | Fly.io Sprites, created by the Courthouse | the Courthouse itself |
| This landing page and docs | Cloudflare (static assets on Workers) | `wrangler deploy` in `apps/site` |
| The code | GitHub | `scripts/ship.sh` |

## Before the first deploy

<Steps>
<Step>

**Sign in** to the three CLIs once:

```bash
gh auth login
npx wrangler login
```

Get a Sprites API token from the Sprites dashboard.

</Step>
<Step>

**Connect the services** in the Sprites dashboard under Connectors: TypeSafe (Jev), AgentMail, Box, Pinecone, Ollama, ElevenLabs and, as a fallback brain, Anthropic. Note each connection ID.

</Step>
<Step>

**Create four AgentMail inboxes**: the family's, and the owner, friend and stranger test senders.

</Step>
<Step>

**Fill in the config** (both files are gitignored):

```bash
cp services/core/.env.example services/core/.env
cp config/owner.example.yaml config/owner.yaml
```

See [Configuration](/docs/guides/configuration) for every value.

</Step>
<Step>

**Check it** without changing anything:

```bash
make deploy-check
```

</Step>
</Steps>

## Ship

```bash
make ship
```

In order, it:

1. checks that no secret is tracked by git or looks like a committed key;
2. runs the Python tests and lint;
3. builds both websites and commits anything left over;
4. creates the public GitHub repository if needed and pushes `main`;
5. deploys the Courthouse to Sprites and waits for `/healthz`;
6. builds this site with the live URL and repository filled in, and deploys it to Cloudflare.

Every step is safe to re-run. Steps 5 and 6 are skipped, with a note, if `.env` is missing or you haven't signed in to Wrangler.

## Deploying the parts on their own

```bash
make deploy        # just the Courthouse
make site-deploy   # just this site (needs `npx wrangler login`)
```

## How the Courthouse deploy works

`scripts/deploy.py` creates the Sprite if it isn't there, uploads the code bundle (Python service, config and the built live site), installs it, writes `.env` with live settings (`PROBATE_FAKE=0`, the clock on, data in `/home/sprite/data`), registers the `courthouse` service on port 8080, restarts it, makes the URL public and waits for `/healthz`. The database is outside the code folder, so redeploys keep the family.

<Callout type="warn" title="Checked against a mock, not yet against Sprites">
  The deploy script has been run end to end against a mock of the Sprites API, and the install has been run on a clean Ubuntu home. The first real run confirms the exec response shape; if an install fails silently, run `sprite exec -s probate-courthouse -- python3 -c "import probate"`.
</Callout>
